三、服务接口摘要
ConfirmationService: issue(req,params,issued_at,nonce?) -> Challenge；accept/decline(req,params,now) -> ConfirmResult；expire(now)；find/has_pending/pending_count；已决请求返回 already_resolved 防重放。TTL 与摘要直接复用 gcp::challenge_fresh / gcp::param_digest。
CatalogService: add/replace/remove/clear；list(category,limit,offset)；search(CatalogQuery)；describe(name_or_alias)；resolve_alias；categories。评分与过滤为纯数据实现，alias -> canonical。
JobService: create(instance,generation,task_id?,ttl,now)；get/advance/set_progress/set_result/fail/request_cancel/advance_cancel；expire(now) 仅清理终态；set_generation 隔离旧代；snapshot/restore 文本持久化。
EventService: publish 单调 seq（自 1）；subscribe 校验 cursor；poll 推进 cursor 并回报 Backpressure（hard 时返回空）；since；set_floor  Expire 旧 cursor。
TraceService: parse/make_traceparent（gcp::valid_traceparent 校验）；begin 复用入站 trace_id、以入站 span 为 parent 生成新 span；end 检查栈顶；new_trace_id/new_span_id 为确定性十六进制。
InvocationService: invoke 依序做规范化 -> 别名 -> 导出期拒绝 -> 高风险 challenge -> sink dispatch -> deferred wait -> 错误水位 -> 脱敏 -> artifact；confirm 校验 challenge 后复用 dispatch；cancel 走 JobService.request_cancel；desensitize 默认 true；无 sink 时返回 result_unknown。
ControlService: 门面暴露 confirmation/catalog/jobs/events/trace/invocation；setter 允许后续 dispatcher 注入 clock、export/risk probe、sink、waiter 与 desensitize 开关。

七、风险与待主代理核对
1. 新增 7 个生产编译单元依赖双登记正确；若 cmake configure 后 source_manifest_guard 报告 production 与 src/*.cpp 不等，优先核对两处清单。
2. gda_unit_tests 链接 godot-cpp 等目标，control_*_test.cpp 由 glob 纳入；需确认 fixture 的 .cpp 仅在测试侧清单登记一次，避免与其他目标重复定义。
3. TraceService 的 new_trace_id/new_span_id 使用函数内静态计数器，跨进程内多个用例时取值递增而非固定；测试只断言长度与合法性，不固定具体值。
4. JobService::snapshot/restore 以 tab 分隔并将字段内 tab/newline/pipe 折叠为空格；仅作为纯数据持久化示意，非二进制兼容格式。
5. InvocationService 的 deferred wait 通过 DeferredWaiter 注入，默认无等待器时保留 pending；真实异步等待须由 dispatcher 提供 waiter，并在 CommandQueue 线程边界外完成。
6. 高风险确认的最终执行门仍在 SpecTool：InvocationService 只产出 needs_confirmation 与 challenge，confirm 成功后才调用注入的 sink；若 dispatcher 注入的 sink 未再次执行 SpecTool 风险判定，须在 dispatcher 侧补齐。
7. 脱敏实现为基于 key=value 的轻量掩码；真实敏感字段清单与脱敏策略应由 dispatcher 复用既有 sanitize_policy，本层只保证默认开启与基本 key 掩码。
