# 测试计划

本文规定本工程作为 **godot-autopilot（GDA）MCP 插件测试床**时的测试目的、目标、约定、证据要求与记录规范。验收项汇总见 [acceptance.md](./acceptance.md)。

## 测试目的

通过"在编辑器里打开 Control Gallery 并逐项验证控件渲染与交互"这一真实任务，评估 GDA 能否让 AI 客户端**仅凭文档与工程文件**完成编辑器 UI 自动化，并客观记录工具与文档的表现。本工程对 GDA 的编辑器 UI 自动化能力尤其重要：节点层级深、控件类型全、属性核对点多。

## 测试目标（评估维度）

1. **场景打开**：能否定位并打开 `control_gallery.tscn`，处理工作树无 `main_scene` 声明的情况。
2. **元素定位**：能否在场景树中定位深层节点（如 `.../Lists/.../VBoxContainer2/Tree`）、在检查器中核对属性、在视口中确认排布。
3. **截图验证**：能否产出编辑器视口截图与运行截图，并与 `screenshots/control_gallery.webp` 对照。
4. **交互执行**：能否驱动分隔拖拽、页签切换、折叠开合、下拉点选等操作并读回结果。
5. **脚本行为**：能否确认 `tree.gd` 的 Tree 填充结果（四项文本 + 两按钮）。
6. **文档自主性**：文档是否只记录"是什么"；是否存在误导验证的内容（错误路径、虚构行为、矛盾数值）。
7. **真实交付**：结论可运行、可复验。不接受"看起来通过"。
8. **记录规范**：问题记录包含五要素（见下）；表现优秀处同样如实记录；不夸大、不贬低。

## 测试约定

- 工程文件（`*.tscn`、`*.gd`、`project.godot` 等）的读取与修改**仅通过 GDA 完成**；允许以只读方式查阅文件用于核对。
- **不主动重启 Godot 引擎**；若引擎意外崩溃，如实记录现象并结束本轮测试。
- 所有结论必须基于实际发生的事件；证据随测试报告留存。
- 测试期间不更新本仓库的 wiki 内容。
- 本项目无存档，删档类操作不适用。

## 执行法（开→定→操→截）

每组验证按四步推进，单组单目标：

| 步 | 名称 | 要求 |
|---|---|---|
| 1 | 开 | 打开主场景（手动指定 `control_gallery.tscn`，因无 `main_scene` 默认） |
| 2 | 定 | 在场景树定位目标节点，在检查器核对关键属性 |
| 3 | 操 | 执行本组交互（拖拽/切换/输入/点选），读回状态 |
| 4 | 截 | 截图存证（编辑器视口或运行画面），标注对应验收项 |

### 验证分组

| 组 | 覆盖 | 证据 |
|---|---|---|
| G1 打开与排布 | 场景 A | 编辑器截图：视口 + 场景树 |
| G2 分隔与页签 | 场景 B | 操作前后对比截图 |
| G3 控件交互 | 场景 C | 运行截图 + 无报错日志 |
| G4 Tree 脚本 | 场景 D | Tree 节点特写截图 |
| G5 截图一致性 | 场景 E | 与官方截图的对照说明 |

### 证据归档

截图随测试报告存入 `report/img/`（仓库根目录的 `report/`，非本文档目录），并在报告中标注每张截图对应的场景编号与验收项。

## 证据要求（含截图）

**逻辑断言不是完整证据；涉及画面效果的验收必须看图。**

| 验收类型 | 必须提供的证据 |
|---|---|
| 属性核对（文本、值、选项、初始态） | 检查器截图或可读回的属性值 |
| **排布与渲染**（面板位置、控件外观） | **编辑器界面截图**：视口 + 场景树/检查器 |
| **运行效果**（交互反馈、Tree 内容、提示条） | **运行界面截图**：真实运行中抓取 |
| **对照一致性**（与官方截图比对） | **并排说明**：指出一致处与尺寸差异原因 |

## 问题记录格式

每个问题必须包含：

1. **触发场景**：在做什么时发生；
2. **详细操作步骤**：可复现的步骤序列；
3. **预期行为**：文档或工具声称的行为；
4. **实际表现**：真实观察到的结果（附证据）；
5. **问题分析**：基于事实链的推断，无法定位根因时如实说明边界。

## 终止条件

- 若因 GDA 的功能缺失或致命缺陷导致验证无法继续，可基于事实终止并转入报告编写。
- 引擎崩溃不尝试重启；记录现象并结束本轮测试。

## 输出

- 测试报告：`report/<YYYY-MM-DD-HH-mm>-report.md`（仓库根目录的 `report/`，非本文档目录）。
- 报告应包含：工具与文档的总结性评估、按优先级排序的优化建议、以及全部问题记录与证据索引。
