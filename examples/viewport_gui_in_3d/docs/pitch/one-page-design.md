# 一页纸设计：GUI in 3D

## 一句话概念

用一个 `SubViewport` 把整套 2D 控件界面渲染成纹理、贴到 3D 场景的一块 Quad 上，并把 3D 空间的键鼠事件换算回视口坐标再喂给界面——**2D 界面住在 3D 世界里，且依然可点可输**。

## 非玩法声明

本演示**没有传统意义上的玩法**：无目标、无敌人、无计分、无胜负、无关卡推进。`gdd/mechanics.md` 与 `gdd/level-design.md` 因此不写虚构玩法，前者写视口复合与输入转发机制，后者写 3D 场景布置实录与观察动线。

## 钩子（为什么值得看）

- 同一套 2D 控件（按钮、输入框、滑杆、下拉框）零改造进 3D，靠的是标准视口纹理链路，而非魔改控件。
- 输入转发的数学过程是显式的（3D 碰撞点 → Quad 局部坐标 → 归一化 → 视口像素坐标），可逐行读 `gui_3d.gd` 验证。
- 相机带 6 秒循环漫游动画，一眼能看出面板是场景中的真实 3D 物体。

## 核心交互循环

```text
看（面板成像于 Quad）→ 指（射线命中 Area3D）→ 点/输（事件换算后 push 进视口）→ 见（控件状态变化呈现在 Quad 上）
```

循环的每一步都可在编辑器里执行并截图验证，见 [test/acceptance.md](../test/acceptance.md)。

## 范围

- 在内：双场景分工、视口纹理成像链、3D 物理拾取、键鼠（含触屏事件结构）转发、billboard 补偿、官方截图对照。
- 在外：任何玩法规则、关卡流程、网络、多语言、本演示之外的 GUI 主题定制（默认主题缩放 2.0 为源库原件配置，见 [tech/tdd.md](../tech/tdd.md)）。

## 成功标准

1. 打开主场景运行，2D 面板清晰成像于 3D 的 Quad 上，与 `screenshots/gui.png` 大致一致。
2. 点击 3D 中的按钮、向输入框打字、拖动滑杆、展开下拉框，均有可见反馈。
3. 相机 6 秒循环漫游持续播放，面板始终可交互（billboard 相关代码路径以脚本实录为准）。
4. 作为 GDA 测试床：上述三条均可由 AI 客户端经 GDA 工具在编辑器内复验并留截图证据。
