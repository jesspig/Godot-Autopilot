# 测试计划

本文规定本工程作为 **godot-autopilot（GDA）MCP 插件测试床**时的测试目的、目标、约定、证据要求与记录规范。

## 测试目的

通过"在编辑器里验证一款已存在的双人联机 Pong demo"这一真实任务，评估 GDA 能否让 AI 客户端**仅凭本 docs/ 与工程文件**完成开场景、核对节点、运行双实例、截图取证的全流程，并客观记录工具与文档在实际使用中的表现。

## 测试目标（评估维度）

1. **工具可用性**：各工具能否完成其宣称的功能；失败时错误信息是否可操作；工具描述与 Skill 文档是否与实际行为一致。
2. **工具完备性**：验证联机游戏所必需的能力是否存在（开场景、读节点属性、运行游戏、抓屏、开第二实例）；缺失时是否存在可接受的替代路径。
3. **参数与数据合理性**：工具参数设计是否自洽；返回值是否足够支撑下一步决策；写入是否有校验、读回是否可信。
4. **文档自主性**：本文档集是否只描述"是什么"；是否存在误导验证的内容（错误路径、矛盾数值、含糊验收）。
5. **真实交付**：最终结论可运行、可复验。不接受"看起来通过"。
6. **流程完整性**：大厅 → 对战 → 胜负 → 退出 → 重开是否构成闭环；断线路径是否干净、可回大厅。
7. **联机正确性**：权限分配、记分方向、出界分工、胜负结算是否符合 [../gdd/mechanics.md](../gdd/mechanics.md)。
8. **记录规范**：问题记录包含五要素（见下）；表现优秀处同样如实记录；不夸大、不贬低。

## 测试约定

- 对工程文件（`*.tscn`、`*.gd`、`project.godot` 等）的核对**优先通过 GDA 只读工具**完成；允许以只读方式直接查阅文件用于交叉核对。
- `project.godot` 缺失段的恢复是测试前置工作，恢复内容以源库原件为准，全程以 `git diff` 留证。
- **不主动重启 Godot 引擎**；若引擎意外崩溃，如实记录现象并结束本轮测试。
- 所有结论必须基于实际发生的事件；证据随测试报告留存。
- 测试期间不更新本仓库的 wiki 内容。

## 分环验证法（本 demo 为现状验证，用"环"替代增量开发）

| 环 | 做什么 | 验收 |
|---|---|---|
| 1 静态核对 | 读全 4 场景 + 4 脚本 + 原件配置，核对本文档 | 与 docs 一致，不一致即记偏差 |
| 2 大厅单实例 | 开主场景，Host，截图等待态；非法 IP、占用端口各试一次 | 状态文案与 [../gdd/ui-hud.md](../gdd/ui-hud.md) 一致 |
| 3 双实例联调 | 第二实例 Join `127.0.0.1`，双方对打，截图两端同框 | 权限/记分/胜负符合 mechanics |
| 4 异常与退出 | 断线一方、Exit Game、再开一局 | 回大厅可用，原因文案正确 |

铁律：单环只验一个主题；失败只在本环定位修复（修文档或记工具问题），不扩大范围；每环留一句话记录（做了什么、截图看到了什么）。

## 双实例联调思路

1. 实例 A 开主场景按 Host（`Waiting for player...` 截图）。
2. 实例 B 开主场景，地址填 `127.0.0.1` 按 Join（`Connecting...` 截图）。
3. 两端应各自隐藏大厅、出现同一球场；分别截图，核对比分 `0`、球近中点、双拍染色。
4. A 只动左拍、B 只动右拍：确认"对方拍不受本端输入影响"（权限验证）。
5. 放球出界：左出界 → 右分 +1；右出界 → 左分 +1（两端截图对比比分一致）。
6. （耗时项，可选）打满 10 分：胜负标签 + Exit Game + 球停；按 Exit 回大厅，两按钮恢复可用。
7. 关 B（模拟断线）：A 应回大厅并显示原因（截图）。

## 证据要求（含截图）

**逻辑断言不是完整证据；涉及画面效果的验收必须看图。**

| 验收类型 | 必须提供的证据 |
|---|---|
| 逻辑行为（记分、权限、显隐、状态文案） | 运行日志或可读回的状态值（截图可选） |
| **大厅与球场摆位** | **编辑器界面截图**：视口 + 场景树/检查器 |
| **运行画面**（对战、比分、胜负标签、Exit Game） | **游戏运行界面截图**：双实例各至少一张同局对打图 |
| 大厅各状态文案 | 运行截图（等待/连接中/失败文案至少各一张，走到哪拍到哪） |
| 断线与退出 | 运行截图（原因文案 + 恢复可用的大厅） |

截图证据建议随测试报告归档（如 `report/img/`），并在报告中标注每张截图对应的环编号与验收项。

## 单机环境限制（如实注明）

- 仅 `127.0.0.1` 回环路径可在单机验证；局域网另一台机器、端口转发、`Find your public IP address` 外链为**未核实**，不得写"通过"。
- 公网 IP 与本地绝对路径属敏感信息：**不写入报告**，截图中如出现一律打码。
- 高延迟、丢包下的"可玩性"在单机回环下无法复现，相关设计注释（`logic/ball.gd:13-15`）只做静态引用，不做行为断言。

## 问题记录格式

每个问题必须包含：

1. **触发场景**：在做什么时发生；
2. **详细操作步骤**：可复现的步骤序列；
3. **预期行为**：文档或工具声称的行为；
4. **实际表现**：真实观察到的结果（附证据）；
5. **问题分析**：基于事实链的推断，无法定位根因时如实说明边界。

## 终止条件

- 若因 GDA 的功能缺失或致命缺陷导致验证无法继续，可基于事实终止并转入报告编写。
- 引擎崩溃不尝试重启；记录现象并结束本轮测试。

## 输出

- 测试报告：`report/<YYYY-MM-DD-HH-mm>-report.md`（仓库根目录的 `report/`，非本文档目录）。
- 报告应包含：工具与文档的总结性评估、按优先级排序的优化建议、以及全部问题记录与证据索引。
