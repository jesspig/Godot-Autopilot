## 2026/10/22 01:20

- **运行时边界写入知识库**（[端口与实例登记](../modules/ports.md) 新增「运行时边界（退出拖慢与强杀残留）」一节，含两小节）：
  - **退出时的最坏耗时约 30 秒**：退出时若还有未响应「队列关闭」的处理请求在途，收割会等它（短预算超时后改为阻塞 join），等待上界 = 处理器剩余时长（MCP 侧分发超时 30 秒、REST 侧主线程派发预算上界 29 秒）——把「崩溃」换成「慢退出」；正常路径（关队列 → 关 MCP 传输 → 停传输）实测为百毫秒量级。
  - **强杀后的端口与登记残留**：编辑器被强杀时监听端口不会立即释放、实例登记会残留；下次启动自动清理同工程的残留登记（进程已死的直接删除并重建全局索引，日志记 `removed the stale instance registration …`；进程仍存活的保留并在绑定失败时点名实例 ID / 进程号 / 端口与登记文件位置，提示不含令牌），但**端口要等占用它的进程真正退出才彻底释放**——自愈只清登记、不夺端口（与「显式端口不自动顺延」一致）。
  - 另明确「**同一工程不要同时打开两个编辑器**」：第二个编辑器会在扩展加载阶段撞上 Godot 的扩展库临时副本占用问题而**可能静默崩溃**（插件代码此时尚未运行，来不及给出提示）；插件侧「同工程已有实例则拒绝启动并提示」是**第二道防线**，只能挡住插件已加载之后的情形。

- **命令行侧新增同工程预检**（[`cli/src/preflight.ts`](../../../cli/src/preflight.ts) 新增模块 + [`cli/src/commands/start.ts`](../../../cli/src/commands/start.ts) 接线）：`gda start` 在**启动编辑器之前**先判该工程是否已有活跃实例。
