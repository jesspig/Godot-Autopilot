## 2026/11/18 12:05 会话可靠性增强（ST-01 行为修复归并概述）

依据 `report/2026-11-18_01-36/analysis.md` 已证实根因实施，九项行为修复（事实以归并后源码为准）：

- **任务存储路径回归集中根**：任务存储改经 [`StoragePaths::task_dir()`](../../../src/core/storage/storage_paths.cpp) → `<gda_home>/.godot-autopilot/tasks/tasks-<stamp>.jsonl`（此前漏 `.godot-autopilot` 段落到 profile 根 `tasks/`）；`tasks_enabled` lifecycle 事件 `path` 属性与存储路径同值。路径变更仅影响新会话，旧文件保留。见 [modules/tools_registry.md](../modules/tools_registry.md) Tasks 节。
- **SDK 日志桥**：装配时 [`route_sdk_logs()`](../../../src/core/observability/log_system.cpp) 把 SDK 日志级别抬到 ≥Error 并路由进 LogSystem——`task store:` 前缀归 Tools 类、其余归 Transport 类，文本加 `MCP SDK: ` 前缀并附 `req=`/`method=` 上下文；task persist 失败等 SDK 侧故障不再静默。见 [modules/core.md](../modules/core.md) LogSystem 节。
- **CLI 中毒诊断**：`stop`/`restart` 优雅失败时经 [`stop-diagnosis.ts`](../../../cli/src/commands/stop-diagnosis.ts) 读工程最新 `gda-*.log` 尾部 64 KiB，命中 `task store: failed to persist` 签名即输出中毒诊断（SDK FileTaskStore compaction bug on Windows）+ `--force` 风险提示（丢弃未保存编辑）；退出码不变，仅增诊断文本。见 [modules/cli.md](../modules/cli.md)。
- **cancel 协议对齐**：编辑器侧 cancel 消息经 [`build_cancel_request_body`](../../../src/tools/base/debugger_access.cpp) 在 `params.request_id` 携带被取消请求 id，游戏桥 `op_cancel` 从 params 取——修复此前顶层/params 错位导致的取消失效。
- **eval 超时回执区分**：编辑器侧 [`build_game_timeout_receipt`](../../../src/tools/base/runtime_ops.cpp) 对 eval 族 op 新增 `timeout_cause`（`script_error`=本请求迟到响应或等待期游戏错误 / `channel_lost`=通道无响应 / `unknown`）；排队后始终未就绪返回 `game_ready_timeout`（`retryable=true`）；`late_results` 按请求关联。游戏侧 `eval_timeout`/`eval_cancelled` 语义不变。见 [modules/entry_runtime.md](../modules/entry_runtime.md) §3.2。
- **ready 门槛消费 scene-ready**：[`decide_game_request`](../../../src/tools/base/ready_policy.hpp) 的 SendNow 要求 ready>0 **且 scene_ready>0**；游戏侧 `gda:ready` body 增 `scene_ready` 字段（注册时 = current_scene 非空；未入树则挂 process_frame 监听、当前场景首次非空时补发一条 `scene_ready:true`）；`wait_ready=true` 排队重放消费场景就绪，force restart 后首调不再撞空树。
- **编辑器启动窗**：无编辑场景根且插件启动 5000ms 内（[`editor_readiness`](../../../src/core/editor_readiness.cpp)），create_scene_node / spec 构建 / play 的失败错误经 `startup_gated_error` 替换为 `startup_in_progress`（`retryable=true`、`retry_after_ms=1000`、hint 建议稍后重试），不再误归因「parent node not found」/「no game process started」。
- **capture 退化拒绝静默成功（有意收紧）**：[`viewport_capture_is_degenerate`](../../../src/tools/domains/capture/capture_ops.cpp) 判据 = 渲染图像任一边 ≤8px（`GDA_CAPTURE_MIN_DIMENSION`）或可见矩形 ≤0；2D 退化触发 3D 回退，两者均不可用返回结构化错误 `no_scene_open`（无场景打开）/ `viewport_degenerate`（附 `captured_viewport`/`size` 诊断）。**迁移说明**：旧行为静默 ok + 占位图（e2e Q1 的 2×2 图），新行为显式错误；描述与 wiki 已登记。
- **并发请求号按连接去重 + 内部 id 改写路由**：[`GodotTransport::submit`](../../../src/core/transport/godot_transport.cpp) 去重键改 (connection_id, request_id)——跨连接同 id 由拒转受理（JSON-RPC id 按连接作用域是协议本义），同连接语义不变；出站请求 id 改写为自增内部 id，响应按内部 id 匹配后回填客户端原 id，`notifications/cancelled` 的 `params.request_id` 同样改写；60s 过期宽限语义不变。CLI 计数器不改。见 [modules/core.md](../modules/core.md) GodotTransport 节与 [security_contract.md](../security_contract.md) §5。

验证：ST-01 各分支由主代理统一构建后分批测试；本段为文档概述，不重复声明测试数值。
