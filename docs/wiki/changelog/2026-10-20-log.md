## 2026/10/20 01:40

- **CLI 在 Windows 上 `gda start` 失败不再留下孤儿进程（子分支归并，合并 `9a6dd89`）**：修掉「回滚拿不到 pid → 编辑器变孤儿」这条 Windows 专属死路。
  - **根因**：Windows 分支原先用 `cmd /c start "" /b` 蹦床拉起编辑器，再 `netstat` 端口反查真实 pid；编辑器**从未监听端口**时反查必然失败，回滚路径因此拿不到 pid，失败后编辑器进程成为孤儿（`gda list` 看不到、`gda stop` 停不掉），回滚能力在 Windows 上基本无效。
  - **启动路径改为直连 `spawn`**：[`cli/src/process.ts`](../../../cli/src/process.ts) 的 `spawnEditor` 删除 `cmd` 蹦床与 `resolvePidByPort` 端口反查，改为 `spawn(exe, rest, { detached: process.platform === "win32" })`——`detached` 让编辑器脱离父进程与控制台（随后 `child.unref()`），规避 Bun 直系子进程随 CLI 退出被作业对象连带杀掉的问题；`spawn` 的返回值即**本次拉起的编辑器自身 pid**，登记表里的 pid 精确等于被拉起的编辑器，**不再按端口/映像名/时间窗反查**，故不误杀无关进程。POSIX 路径不变。
  - **存活判定与系统语言无关**：`isAlive` 在 Windows 上改为解析 `tasklist /FO CSV` 的 pid 字段（正则 `^"[^"]*","(\d+)"`）。此前靠「输出是否以 `INFO`/`消息` 开头」判断「无匹配任务」，而中文 Windows 实际输出「信息:」→ 恒判为存活，使终止确认轮询超时并把**已终止**的进程误报成「无法终止」。进程表查不到时**保守返回存活**——不得因查不到就跳过终止动作而留下孤儿。
  - **失败回滚三态与可执行补救指令**：`terminateProcess` 返回 `already-exited` / `terminated` / `failed`，`terminationNote` 对应三条文案（`the editor process (pid N) had already exited` / `… was terminated` / `… could not be terminated, stop it manually: taskkill /F /T /PID N`，POSIX 为 `kill -9 N`）；引擎不可执行时报 `failed to launch the editor executable: ENOENT: …` 并提示检查 `--godot` 路径，而非笼统的 `failed to spawn`。
  - **覆盖**：[`cli/tests/detach.test.ts`](../../../cli/tests/detach.test.ts) 断言父进程退出后编辑器仍存活，且 Windows 上返回 pid 的映像名就是被拉起的可执行文件（脱父语义 + pid 归属）；[`cli/tests/lifecycle.test.ts`](../../../cli/tests/lifecycle.test.ts) 新增「就绪超时」与「进程立即退出」两条用例，断言回滚后编辑器已消失、不留 `.pending-` 日志、不登记实例；[`cli/tests/process.test.ts`](../../../cli/tests/process.test.ts) 新增存活判定、终止三态与补救指令、引擎不可执行三条用例。契约口径同步到 [T0 安全边界与并发契约](../security_contract.md) §3.4。
