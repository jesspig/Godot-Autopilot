- **依赖管理：FetchContent → git submodule（纯 submodule，零 FetchContent）**：分支 `feature/submodule-deps`（从 `develop` 切出）。
  - **动机**：`_deps` 缓存位于 `build/<preset>/` 下，而 `.gitignore:2` 忽略整个 `build/`，因此依赖源码无法随仓库流转，换机或内网克隆后必然需要重新访问 GitHub —— 在无外网或 GitHub 不可达的环境下构建直接失败。改为 submodule 后源码位于 `third_party/`，不被 gitignore 排除，检出后 configure 零网络访问。
  - **前置调研结论**：三个依赖（godot-cpp / mcp-cpp-sdk / googletest）上游均**无嵌套 FetchContent**、无 `third_party/`、无 `ExternalProject`；godot-cpp 的 API JSON（`gdextension/extension_api-4-7.json`）与其 Python 绑定生成脚本全部在仓内，仅需本机 Python3；mcp-cpp-sdk 的 `cmake/FetchDependencies.cmake` 内只有 `find_package(OpenSSL QUIET)` 且无任何 `FetchContent_Declare`。故 submodule 化不残留隐藏联网点。
  - **落地**：`.gitmodules` + `third_party/{godot-cpp,mcp-cpp-sdk,googletest}`，gitlink 锁定 `507ed9d840c01a3c5b2a39af8bb4000bfac30bf5`（godot-cpp `10.0.0-stable`）、`e2ed352da5c2735f1f7564be664fdef0bbaad3bb`（mcp-cpp-sdk `0.3.4`）、`b514bdc898e2951020cbdca1304b75f5950d1f59`（googletest `v1.15.2`）。`cmake/FetchDependencies.cmake` 经 `git mv` 改名为 `cmake/Dependencies.cmake` 并重写为纯 `add_subdirectory`，新增 `gda_require_submodule()`：子模块缺失即 `FATAL_ERROR` 并提示 `git submodule update --init --recursive`，**故意不做网络回退**以保证构建行为确定（回退会让内网环境在 configure 中途抛出难定位的 git 报错）。子项目二进制目录为 `${CMAKE_BINARY_DIR}/_sub/<name>`。见 [build.md](../build.md)。
