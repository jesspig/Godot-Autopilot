  - **坑 1：MSVC `error C3493` 与 `/Zc:lambda`**。**现象**：MSVC 路径首次全量编译失败于 `src/tools/runtime_ops.cpp(891,33): error C3493` 与 `tests/unit/tool_catalog_test.cpp(93,27): error C3493`。**根因**：MSVC **拒绝 lambda 经 `[&]` 隐式引用捕获局部 `const`/`constexpr` 变量**，clang（clang-cl）接受同一写法；典型形态是函数内 `constexpr size_t N = 256;` 配合 `std::thread([&s]{ ... s.size() > N ... })`，经最小复现逐条定位，属编译器实现开关而非源码违规。**修法**：[`cmake/CompilerOptions.cmake:48`](../../../cmake/CompilerOptions.cmake) 的 MSVC 分支（`elseif(MSVC)`，即真正的 cl.exe；clang-cl 命中的是前面的 `if(CMAKE_CXX_COMPILER_ID MATCHES "Clang")` 分支，**不受影响**）追加 `/Zc:lambda` —— 这是 MSVC 的 lambda 标准符合性开关，**CMake 默认不启用**。加上后**零源码改动**即可编译，并顺带拉齐 clang 与 MSVC 的行为差异。
