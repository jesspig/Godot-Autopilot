- **REST 接口面落地（`/api` 端点集）**：插件在**同一个监听端口**上新增一套 REST 风格的端点面，与既有 MCP 面（`/mcp`）并列。
  - **端点契约**（[`src/core/api_surface.cpp`](../../../src/core/api_surface.cpp)）：前缀 `/api`（常量 `GDA_API_PATH`），共 **8** 条端点——`GET /api`（服务与端点清单）、`GET /api/tools`（`query` / `category` / `tags` 过滤 + `limit` / `offset` 分页）、`GET /api/tools/<工具名>`（详情）、`POST /api/tools/<工具名>`（**请求体直接是参数对象**，无 `arguments` 外层包装）、`POST /api/batch`（`{"operations":[{"tool","args"}],"stop_on_error"}`）、`GET /api/health`（**免认证**）、`GET /api/endpoints`（端点表，与 MCP 侧资源 `godot://endpoints` 共用同一份文档）、`GET /api/openapi.json`（OpenAPI 3.0.3）。路由挂载在 [`src/core/api_server.cpp`](../../../src/core/api_server.cpp)，与 MCP 面共用同一自建 HTTP 传输层与同一把 `CommandQueue`。
  - **认证**（[`src/core/api_auth.cpp`](../../../src/core/api_auth.cpp) / [`src/core/api_token.cpp`](../../../src/core/api_token.cpp)）：除 `/api/health` 外均需 `Authorization: Bearer <令牌>`；令牌为 **32 字节随机值的十六进制**（`GDA_API_TOKEN_BYTES = 32`），来源优先环境变量 `GODOT_AUTOPILOT_API_TOKEN`、其次工程级令牌文件；比对用常量时间比较；签发后写入实例登记供 CLI 读取。
  - **错误信封归一**（[`src/core/api_envelope.cpp`](../../../src/core/api_envelope.cpp)）：工具失败统一带 `error` 与 `code`；状态码由**码**决定而非文案——401 / 400 / 404 / 403 / 503 / 504 / 500，其余归 422。**超时标记已取消且不可重试**（`main_thread_timeout` 的 `retryable` 由 true 改为 false，副作用可能仍落地）；队列不可用返回 `queue_unavailable`（`retryable=true`）。
  - 契约与已知限制见 [REST 接口面](../modules/api.md)。

- **插件控制面板补齐写类与破坏性授权开关（行为变更的恢复路径补齐）**：授权已由「仅拦进程 / 代码执行 / 游戏运行时三类」扩展为**三档七能力**（读类默认放行、写类默认拒绝、危险类默认拒绝需显式开启），但控制面板此前只有三个复选框（"Allow code_execute" / "Allow game_runtime" / "Allow user tools"），**写类（`write`）与破坏性（`destructive`）没有开关**——用户被默认拒绝后只能改环境变量或手改配置文件才能恢复，UI 路径断了。本批把两个开关补上。
  - **面板实现**（[`src/ui/mcp_config_dock.cpp`](../../../src/ui/mcp_config_dock.cpp) / [`.hpp`](../../../src/ui/mcp_config_dock.hpp)）：新增 "Allow write" 与 "Allow destructive" 两个复选框，沿用既有 `_on_allow_*_toggled` → `authorization::allow_list_add` / `allow_list_remove` 模式（含 `monitor::ui_action` 与 `monitor::security` 两类事件）；初始勾选状态取自**当前实际允许列表**（`GODOT_AUTOPILOT_ALLOW` 环境变量优先于配置 `allow` 键）。
  - **面板开关的能力清单由三项扩为五项**（[`src/tools/authorization.hpp`](../../../src/tools/authorization.hpp) 的 `capability_has_dock_toggle`）：`code_execute` / `game_runtime` / `user_tools` / `write` / `destructive`；`read` 无需授权故无开关，`process` 仍只能经环境变量或配置键开启。拒绝响应的 `enable` 文案随之对 `write` / `destructive` 也给出面板指引。
  - **行为变更（对外）**：写类工具（写文件、写工程与编辑器配置、弹用户可见提示、改窗口与注入输入）与破坏性工具（销毁既有对象的不可逆操作，当前唯一声明者 `delete_display_window`）**默认拒绝**，未授权时返回 **403 `authorization_required`**；**既有 MCP 与 REST 调用都会被拒**——REST 面的令牌只解决「谁在调用」，不替代能力门。
  - **一行开启方式**：把 `write` / `destructive` 加入允许列表——设环境变量 `GODOT_AUTOPILOT_ALLOW=write`（逗号分隔，或 `all`，须重启引擎），或在插件控制面板勾选 "Allow write" / "Allow destructive"（**下一次工具调用即生效，无需重启引擎**），或在配置的 `allow` 键里加入 `write` / `destructive`。
  - **增删语义**：勾选即加入、取消即移除，且**取消某一项不影响其它项**——允许列表为 `all` 时先展开成全部已知能力再逐项删除，其余能力保留。
