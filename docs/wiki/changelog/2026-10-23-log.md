  - **E-1a `gda restart`**：定位规则与 `stop` 完全一致（位置参数 `<id>`，或 `--id` / `--port` / `--project` 三选一），只作用于 CLI 本地注册表；流程为「优雅停止（`--force` 才强杀）→ **固定等待 10 秒**（不受 `--wait` 影响）→ 移除旧条目 → 按原端口 / headless / godot 路径重新拉起 → 输出 `previous` 与新实例视图」。停止阶段超时**不启动替代实例**，避免同一工程双开（扩展加载期可能静默崩溃）。
  - **E-1b 多实例路由**：`/i/<实例 ID 或端口>/api[/…]` 与 `/i/<ref>/mcp` 精确转发；缺省 `/api/...`、`/mcp` 在唯一活跃实例时自动转发，多个活跃返回 **409 `instance_ambiguous`**（附 `candidates`），零个返回 **503 `no_active_instance`**；目标不可达 **503 `instance_unavailable`**，上游连接失败 **502 `upstream_unreachable`**，上游超时 **504 `upstream_timeout`**；无匹配路径 **404 `instance_not_found`** / **404 `not_found`**。
  - **E-1c 双面转发**：默认 `127.0.0.1:9700`，`--bind` 只接受环回地址（`127.0.0.1` / `::1` / `localhost`）；`GET /control/health` 免认证，`GET /control/instances` 需 Bearer 且**不返回 `apiToken`**，其余路由均需认证；令牌文件 `<集中根>/control.token`（32 字节随机值的十六进制、`0600`，已存在则复用）；转发丢弃客户端 `Authorization` 与逐跳头并注入目标实例令牌，响应加 `X-GDA-Instance` 并**边到边流式透传**（MCP SSE 可直接穿过）；`--timeout` 只覆盖到响应头，不切断长连接。
- **明确不做 HTTP 启停端点**：控制面只提供只读查询（`/control/health`、`/control/instances`）与转发，启停仍只在 CLI 侧（`start` / `stop` / `restart`）。理由是把本机进程控制暴露成 HTTP 端点，会让任何能访问该端口的客户端获得启停编辑器的能力，风险大于收益；这与「控制面是纯代理、不复制工具语义」的定位一致。

- **缺陷修复：控制面按 CLI 实例标识寻址返回 404**。`gda list` 显示的实例标识是 `p<pid>`，而控制面此前只接受插件侧 `instance_id`（`gda-...`）与端口，`/i/p9672/...` 因此一律 404。现 `/i/<ref>/...` 接受三种寻址，匹配优先级为：① 插件 `instance_id` 精确匹配；② CLI 标识 `p<pid>`（按实例记录里的进程号匹配，存活记录优先）；③ 纯数字端口（1–65535，匹配实例端口或声明的 MCP / REST 端点端口）。`gda list` 的标识可直接作为 `<ref>`；三种均无匹配仍返回 404 `instance_not_found`。真机冒烟：`/i/gda-daa757f3-9672-1792697320437/...`、`/i/p9672/...`、`/i/9530/...` 三种寻址均返回 200。
- **缺陷修复：headless 实例无法优雅停止**。Windows `taskkill` 不带 `/F` 只向窗口发关闭请求，headless 进程没有窗口，故 `gda stop` 必然等到超时、`gda restart` 因停止失败必然拒绝重启。现 `stop` 与 `restart` 统一经 `stopMethod(force, headless)` 选择：显式 `--force` 或目标无窗口 ⇒ 强制停止，否则优雅停止。有窗口实例的优雅停止超时行为不变——不静默升级为强制，返回失败并提示 `--force`，保留登记；无窗口实例输出的 `method: "force"` 是预期值，不是回退到强制兜底。真机冒烟：headless 实例 `gda stop --project ...`（未传 `--force`）在秒级成功，`method: "force"`，进程已退出。
