## 2026/11/17 01:50 Game Jam 生成器 v2（题库 50、随机抽样、项目创建与收藏）

- **题库 v2**：[`devtools/data/gamejam/themes.json`](../../devtools/data/gamejam/themes.json) 升为 `schema_version: 2`，共 **50 条**。新增 `organizer` / `event` / `edition` / `year` / `source_title` / `source_kind` / `rules_url` / `verified_at` / `tags` / `design_constraints`；`source` 改为由 `event + edition` 派生，`source_url` 必填。`keywords` / `concept_ideas` 至少 5 条。
- **来源与约束**：42 条官方来源，8 条 Wikipedia/Web Archive 归档来源（`source_kind: archive`）；每条都有可验证 `source_url`，无来源主题未收录。`design_constraints` 只收设计/内容层限制（玩家数量、类型、内容分级、输入方式、分辨率/配色、必须包含或禁止的元素等）；时间、团队、引擎、提交平台、源码公开、素材授权、AI 工具等运营/生产规则不写入。15 条主题有实际创意约束（如 Brackeys 的 NSFW 禁令、GBJAM 的 160×144/4 色/Game Boy 按键、js13k 的 13KB、Pirate 的内容禁令、Acerola 的英文与可玩核心循环要求），其余为 `[]`。赛事模板由用户固定维护；当前模板未包含创意约束占位符，因此 `design_constraints` 仅保留在题库与 `jam.json`，`rules_url` 仍保留在元数据中供追溯。
- **随机抽样**：每次抽题从 `keywords` 与 `concept_ideas` 各自无放回抽取 3–5 条并打乱顺序，只渲染子集；抽样快照写入 `jam.json`。同一主题重复抽到会得到不同 brief，intake 刷新而最终项目保留当轮快照。
- **项目创建流**：`jam` 只生成/刷新 `examples/<theme_id>/project/` intake（`config/name="project"`）；`jam create --theme <id> --name <name> [--slug <slug>]` 复制 intake 到 `examples/<theme_id>/<slug>-<hash8>/`，写入 `config/name` 与 `jam.json`；作品说明文档完全按 `GAMEJAM.md` 的提交要求处理，不生成额外文档或模板。`hash8` 为 `sha256(name + timestamp + attempt)` 前 8 位；ASCII slug 缺失时要求显式 `--slug`。
- **目录与发现**：`examples/` 改为 `<主题>/<项目>` 嵌套；新增 [`devtools/lib/jam_projects.ts`](../../devtools/lib/jam_projects.ts) 读取 `jam.json` 并递归发现项目，跳过 intake 与 `.git`/`.godot`/`addons`/`build`/`node_modules`；`deploy`/`clean` 未传 `--project` 时只看到最终项目。
- **收藏**：新增 `jam list [--projects] [--json]` 与 `jam index [--json]`；`jam index` 生成 `examples/INDEX.md`，列出项目名、主题、赛事、年份、创建时间与工程路径。项目仍保留在本地 `examples/`，不入库。
- **e2e 技能**：[`gda-e2e-testing`](../../../.agents/skills/gda-e2e-testing/SKILL.md) 改为「抽题 → 读题 → 命名 → `jam create` → 部署/打开最终项目 → 按 `GAMEJAM.md` 提交要求准备作品说明文档 → 开发 → `jam index`」；禁止在 intake 中开发、禁止手工创建项目、禁止一轮内重复抽题。
- **测试**：重写 [`cli/tests/jam.test.ts`](../../cli/tests/jam.test.ts) 并新增 [`cli/tests/jam_projects.test.ts`](../../cli/tests/jam_projects.test.ts)，覆盖 v2 校验、3–5 抽样、约束渲染、intake 刷新、slug/hash、同名重试、显式目录不覆盖、项目扫描、used 判定、列表与索引、递归发现与 intake 跳过。`bun test cli/tests` 实测 **37 个测试文件 / 345 项（322 pass + 23 skip + 0 fail）**。
- **验证**：`bun run typecheck` 通过；`jam --list` 输出 50 条；`jam --theme game_off_2026_shift --json` + `jam create --name "Smoke Test" --slug smoke-test` 生成 intake 与最终项目，核对 `GAMEJAM.md`、`project.godot`、`jam.json`，并确认未生成额外作品说明文档或模板；`jam list --projects` 与 `jam index` 正常；冒烟产物已清理。来源 URL HTTP 检查中 44 个唯一 `source_url` 全部返回 200。
