- **依赖管理 FetchContent → git submodule（纯 submodule，零 FetchContent）**：分支 `feature/submodule-deps`。`_deps` 位于被 `.gitignore` 排除的 `build/` 下，无法随仓库流转，换机或内网克隆后必然重新访问 GitHub；改为 submodule 后源码在 `third_party/`，检出后 configure 零网络。`cmake/FetchDependencies.cmake` 经 `git mv` 改名 `Dependencies.cmake` 并重写为纯 `add_subdirectory`，新增 `gda_require_submodule()` 缺失即 `FATAL_ERROR`、**故意不做网络回退**。CI build job checkout 加 `submodules: true`，cache 路径改 `third_party/` 三目录、key 取 gitlink sha（不可用 `hashFiles('.gitmodules')`，否则升级 commit 会命中旧源码缓存）。**验证**：代理指向不可达地址时 configure 仍成功（零网络）；构建产出 `godot-autopilot.dll` 与 `gda_unit_tests.exe`；L1 **394/394 全绿**（含两守卫与 `skill_scripts`，225.99 s）。详见 [2026-10-10-log.md](changelog/2026-10-10-log.md)
- **文档同步**：`build.md`（新增「依赖获取」小节与三依赖 tag/commit 表）、`conventions.md`、`tests.md`、`overview.md`、`security_contract.md`、`tests/README.md`、`AGENTS.md`（硬约束改为 submodule 检出要求）；顺带修正 `demo/networking_multiplayer_pong/docs/tech/tdd.md` 中「删除 `_deps/` 缓存」的过时约束。详见 [2026-10-10-log.md](changelog/2026-10-10-log.md)
- **构建环境自适应（生成器双路径 + Python 探测放宽）**：原先 `CMakePresets.json` 写死 `generator: Ninja`，无 ninja 的机器直接 configure 失败。现由 `hidden` 的 `base-debug`/`base-release` 承载配置并经 `inherits` 派生出 `debug`/`release`（Ninja）与 `debug-portable`/`release-portable`（省略 generator，由 CMake 发现平台默认生成器），共用同一 `build/{debug,release}`；`scripts/config.py:resolve_preset` 按 `shutil.which("ninja")` 选路，`cmake_ops`/`test_ops` 统一调用，**命令行接口零变更**、CI 无需改动。踩到并修掉一个坑：省略 generator 时 CMake 会**沿用 cache 中已有的生成器而非重新发现**，故须在 configure 前比对并主动清空（cache 条目形如 `CMAKE_GENERATOR:INTERNAL=Ninja`，类型在首个冒号之后）。Python 探测改为 `find_package(Python3)` 优先（不命中 Store 存根、认 `python3.12`），配合 `_subprocess_env()` 前置 `sys.executable` 目录。详见 [2026-10-10-log.md](changelog/2026-10-10-log.md)
- **多配置生成器适配（三个只有真跑起来才暴露的坑）**：MSVC 路径首次全量编译失败于 `error C3493`，最小复现定位为**MSVC 拒绝 lambda 经 `[&]` 隐式引用捕获局部 `const`/`constexpr` 变量**（clang 接受），加 `/Zc:lambda`（MSVC lambda 符合性开关，CMake 默认不启用）零源码改动修复；多配置生成器（VS/Xcode）产物多一层 `Debug`/`Release` 子目录，新增 `config.py:artifact_dir()` 按**实际生成器**判定并改 `deploy.py` 取用；ctest 缺 `-C` 会让 431 个测试只注册 40 个且三例报 `Missing "-C <config>"`（`gtest_discover_tests` 的发现文件名带配置名），在 portable 的 build/test preset 上加 `configuration` 字段由 CMake 自动翻译。**验证**：无 ninja 无 DevShell 的普通 PowerShell 中自动清空切换到 MSVC 19.51 + VS 生成器，构建产出齐全、L1 **394/394 全绿**（72.16 s）、`deploy` 6 个目标全部成功。详见 [2026-10-10-log.md](changelog/2026-10-10-log.md)
