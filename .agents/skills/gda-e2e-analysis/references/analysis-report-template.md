# analysis.md 报告结构模板

报告写到最新轮目录下的 `analysis.md`，与 `report.md`、`evidence.md` 同级，保持该轮自包含。沿用端到端报告的 `Q<n>` 编号；分析中新发现的问题编号 `A1`、`A2`… 并注明来源；建议沿用 `S<n>`。

只把有行为对照证据支撑的经验写入第 13 节；置信度取高/中/低，可复用范围取跨 demo/同 demo/单次；证据不足的观察写入第 11 节，不进入经验库。第 14 节登记回放材料，供后续离线评估。随分析推进增量写报告；实施后追加验证结果。第 9 节列出「待下一轮端到端验证项」。

```markdown
# <demo> 端到端报告根因分析与优化

## 0. 输入与范围
- 报告路径 / 轮目录 / GDA 版本 / Godot 版本 / 本项目 commit
- MCP SDK 路径与 commit / 绑定层路径与 commit
- 分析范围与未覆盖范围

## 1. 结论摘要
- 失败项数量与根因分布
- 采纳 / 不采纳 / 待确认数量

## 2. 失败项清单
| 编号 | 对应报告位置 | 现象 | 可复用性 | 根因层 | 根因结论 | 证据强度 |

## 3. 逐项根因与调用链
### Q1
- 触发条件与复现步骤
- 调用链
- 本项目证据（文件:行号）
- MCP SDK 证据（传输/分发/工具注册，文件:行号）
- 绑定层证据（GDExtension C++ 绑定的头文件/实现，文件:行号）
- 根因结论与反证
- 不确定性与未验证项

## 4. 关联分析
- 共同根因分组
- 级联影响
- 失败项 × 根因层矩阵

## 5. 报告建议逐项评估
| 建议编号 | 建议 | 候选类型 | 回放证据 | 对照结果 | 合理性 | 可行性 | 收益 | 风险 | 影响范围 | 一致性 | 证据 | 结论 |

## 6. MCP 同类工具调研
- 工具/项目 / 生态 / 相似功能 / 架构 / 性能 / 安全 / 问题处理 / 来源

## 7. 交叉验证与优化候选
- 内部证据与外部实践的一致点、冲突点
- 可借鉴、不适用、需谨慎对待

## 8. 增强设计与实施
- 采纳项的增强设计
- 变更文件与行号
- 兼容性与回滚

## 9. 验证方式与结果
- 构建、测试、抽样核对
- 未覆盖项
- 待下一轮端到端验证项

## 10. 未采纳建议与替代方案
## 11. 证据不足、不确定性与残余风险
## 12. 证据索引
## 13. 可复用经验条目
| 编号 | 适用条件 | 教训 | 证据（Q/S + 对照） | 置信度 | 可复用范围 |
## 14. 回放索引
- 本轮可回放材料：`report.md`、`evidence.md`、关键 Q 编号
- 基线行为与候选对照
- 历史轮次及其适用条件
```
