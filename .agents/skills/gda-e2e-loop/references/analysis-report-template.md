# analysis.md 报告结构模板

报告写到最新轮目录下的 `analysis.md`，与 `report.md`、`evidence.md` 同级，保持该轮自包含。沿用端到端报告的 `Q<n>` 编号；分析中新发现的问题编号 `A1`、`A2`… 并注明来源；建议沿用 `S<n>`（以 `digest.json` 的 `q_items`/`s_items` 核对无遗漏）。

**只读边界**：只创建或更新 `analysis.md`；`report.md`、`evidence.md`、`img/`、`digest.json`、`coverage.json`、`trace-snapshot.jsonl` 与工程 `GOAL.md` 一律只读，不删除、不回写、不覆盖已有轮目录。

**证据与真实性**：只把有行为对照证据支撑的经验写入第 16 节；置信度取高/中/低，可复用范围取跨 demo/同 demo/单次；证据不足的观察写入第 14 节，不进入经验库。证据强度统一取直接证据/间接证据/推测（未验证）。无历史轮或证据不足时明确标注「未验证/无历史回放」，禁止编造历史 Q 条目、行号、对照结果或库条目。第 18 节登记回放材料与降本指标。随分析推进增量写报告；阶段 3 实施后追加验证结果。第 12 节列出「待下一轮端到端验证项」。

**digest 对齐**：硬指标一律来自 `bun run gda-dev-tools harness digest --round <轮目录>` 的 `digest.json`，消费点见 `goal-and-verifier.md`；软指标由独立子代理判定，开发者不自评；反作弊以 `digest.suspected_gaming` 为准。范围口径统一为「功能单元 ≥3、完整通关流程 ≥5 分钟」，不写「单单元 ≥5 分钟」。

```markdown
# <轮目录> 端到端报告根因分析与优化

## 0. 输入与范围
- 报告路径 / 轮目录 / GDA 版本 / Godot 版本 / 本项目 commit
- 依赖 SDK 路径与 commit / 绑定层路径与 commit
- digest 路径 / schema / 来源轮次（digest.round）
- GOAL 终态：active | paused | budgetLimited | usageLimited | complete | unmet（取自对应工程 GOAL.md 末态，与报告头部对照）
- 冻结快照：本轮读到的运行时数据 `.handoff/library/HARNESS_LIBRARY.md` 条目 id 与状态清单（规则见 `HARNESS_LIBRARY.md` 模板）；digest.json / coverage.json / trace-snapshot.jsonl 版本
- 分析范围与未覆盖范围；历史轮是否可用（无历史轮标注「未验证」）

## 1. 结论摘要
- 失败项数量与根因分布
- 采纳 / 不采纳 / 待确认数量
- verifier 结论（硬指标/软指标是否均通过）与 suspected_gaming 结论
- 覆盖结论：目标 253/253，实际 <N>/253，未覆盖工具与理由摘要

## 2. 失败项清单与真伪三分类
| 编号 | 对应报告位置 | 现象 | 真伪分类（真实缺陷/偶发/Agent误操作） | 判定依据（可验证信号） | 可复用性 | 根因层 | 根因结论 | 证据强度 |
- 只有判为「真实缺陷」的条目进入第 3 节根因与阶段 3 修复；偶发/误操作类写明依据与后续处置，不进修复。

## 3. 逐项根因与调用链
### Q1
- 触发条件与复现步骤
- 调用链
- 本项目证据（文件:行号）
- 依赖 SDK 证据（传输/分发/工具注册，文件:行号）
- 绑定层证据（GDExtension C++ 绑定，文件:行号）
- 根因结论与反证
- 因果三元组：动作=<...>；条件=<...>；后果=<...>
- 不确定性与未验证项

## 4. 关联分析
- 共同根因分组 / 级联影响 / 失败项 × 根因层矩阵

## 5. 报告建议逐项评估
| 建议编号 | 建议 | 候选类型 | 回放证据 | 对照结果 | 对照证据强度 | 合理性 | 可行性 | 收益 | 风险 | 影响范围 | 一致性 | 证据 | 结论 |

## 6. Dream-RSI 离线回放记录
- 模拟器池：参与回放的历史轮目录清单（含跨 demo 标注与当前证据重验说明）；无历史轮写「无历史回放，未验证」
- broad 批量探索：候选总数与来源，每个标注证据强度
- deep 深挖：进入完整 Propose–Probe–Compose 的高影响候选及依据
- 离线对照：使用的历史 trace/evidence/Q 条目；证据不足时用最小复现代替并注明
- 覆盖缺口转候选：逐项列出 digest.coverage_gaps → 真实功能需求判断 → 候选或「无需求，原因」
- 降本指标：真实轮次调用数 / 候选探索数 = <n>/<m>（为 0 写明「未执行真实轮次，仅离线回放，未验证」）

## 7. 混合 verifier 判定
- 硬指标（来源 digest.json，只读）：
  | digest 字段 | 消费值 | 判定用途 |
  | q_items / s_items | | 核对编号齐全无遗漏 |
  | levels / playtime_minutes | | 判「功能单元 ≥3 且完整通关 ≥5 分钟」 |
  | causal_triples | | 核对动作→条件→后果结构 |
  | coverage_gaps | | 作第 6 节候选来源 |
  | coverage_used / coverage_invalid_touches / evidence_rows / suspected_gaming | | 有效覆盖、无效触碰、证据行数、反作弊 |
  | round / schema | | 溯源与版本核对 |
- 软指标（独立子代理判定）：玩法手感 / 主题诠释 / 画面表现 / 单元可玩性 → 通过/不通过 + 依据
- 综合结论：两类均通过才判 verifier 通过；任一不通过写明回退或补齐动作

## 8. 反作弊与覆盖缺口
- 固定口径行：`覆盖 <N>/253，有效 <M>，无效触碰 <K>，suspected_gaming=<是|否>（依据：...）`
- digest.suspected_gaming=true 时：覆盖不进经验库，相关条目只标候选/弃用；写明依据，不自评通过
- coverage_invalid_touches 剔除情况：列工具名、原因与缺失要素
- 未覆盖工具逐项列原因；禁止为补缺口做无开发意图的调用

## 9. 同类工具调研（按需）
- 工具/项目 / 生态 / 相似功能 / 架构 / 性能 / 安全 / 问题处理 / 来源 URL + 检索日期

## 10. 交叉验证与优化候选
- 内部证据与外部实践的一致点、冲突点；可借鉴/不适用/需谨慎

## 11. 增强设计与实施（阶段 3，授权后追加）
- 采纳项的增强设计：组件归属、收益、性能/安全/便利性/体验、兼容性、最小变更、回滚、新增测试
- 变更文件与行号；对照 probe 结果；构建与测试结果

## 12. 验证方式与结果
- 构建、测试、抽样核对；未覆盖项；待下一轮端到端验证项

## 13. 未采纳建议与替代方案

## 14. 证据不足、不确定性与残余风险

## 15. 证据索引
- 引用轮目录、Q/S 编号、digest.json 路径、trace/log 路径、截图相对路径

## 16. 可复用经验条目
| 编号 | 适用条件 | 教训（动作→条件→后果） | 证据（Q/S + 对照来源） | 置信度 | 可复用范围 |

## 17. 共享库更新清单
| id | 状态 | 可编辑面 | 动作（新增/修订/冻结/弃用） | 依据（对照证据 / digest 字段） |
- 无证据支撑的轮次不写库条目；库为空时写明「当前无条目，待真实轮次证据写入」

## 18. 回放索引与降本指标
- 本轮可回放材料：report.md、evidence.md、digest.json、coverage.json、trace-snapshot.jsonl、关键 Q 编号
- 基线行为与候选对照；历史轮次及适用条件（无历史轮标注未验证）
- 降本指标：真实轮次调用数=<n>；候选探索数=<m>；单候选真实调用成本=<n>/<m>（m>0）
```
