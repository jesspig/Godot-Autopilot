# 分代理与盲测的依据

本文件只解释四阶段设计的依据，不改变执行规则；执行以 `SKILL.md` 为准。

## 已核实的依据（2026-11-21 联网检索）

同一上下文「执行 + 自审」存在系统性偏差，证据强。ICLR 2024《LLMs Cannot Self-Correct Reasoning Yet》显示无外部反馈时自纠常使性能下降；ACL 2024《Pride and Prejudice》显示 self-refine 会放大自身偏见；NeurIPS 2024《LLM Evaluators Recognize and Favor Their Own Generations》直接证实同一模型既生成又评估会自偏好；2025 年 1414 组 LLM-as-judge 研究发现验证者识别有效输出 TPR>96% 但识别无效输出 TNR<25%；2026 年 agent loop 研究记录「54 个周期全自称改进、56% 实测零或负向」。Science Advances 2025（192,000 次评估）进一步证明盲测/去身份化能消除署名偏差。来源与逐条判定见 `docs/wiki/changelog/2026-11-21-log.md`。

## 关键限定

文献支持的处方不是「多加几个 agent」，而是**独立 + 外部 grounding**。同源模型的多实例会共享盲点、错误收敛；Reflexion 作者也坦言同模型自评无形式保证。因此三条硬机制缺一不可：

1. **上下文隔离**：每个子代理只拿结构化交接物，看不到其他阶段的内部推理。
2. **确定性 grounding**：真伪判定必须落到 `digest.json`、真实源码行号、构建/测试结果等可验证信号，不以「另一个模型的意见」为终判。
3. **盲测**：测试/复测子代理不接触源码，只按真实操作观察现象，避免照着代码路径去「验证」而非「测试」。

四阶段设计（测试盲测 → 分析定案 + 独立审查 → 修复 → 复测盲测）即以上三机制的组合；审查子代理若与分析子代理同族模型，须额外用确定性信号复核，分歧升级用户。
