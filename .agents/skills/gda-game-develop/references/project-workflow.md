# 工程流程细则

本文件承接 SKILL.md 的命令、字段与判据，按需加载；规则强度与阈值以 SKILL.md 为准。文中路径均相对仓库根。

## 命令与参数

| 用途 | 命令 |
| --- | --- |
| 抽题 | `bun run gda-dev-tools jam --json`；指定主题加 `--theme <id|展示名>`（先匹配 id 再匹配唯一展示名） |
| 读题产物 | `intake_path/GAMEJAM.md` 与 `intake_path/jam.json`；提取主题、抽样关键词、概念灵感、创意约束、提交要求与评审维度。创意约束与模板建议冲突时以约束为准 |
| 抽题记录字段 | `theme_id`、`theme`、`source`、`intake_path`、`draw_id` |
| 创建工程 | `bun run gda-dev-tools jam create --theme <theme_id> --name "<项目名>" --slug "<slug>" --json`；返回的 `path` 为工程目录，只应含 `project.godot`、`GAMEJAM.md`、`jam.json` |
| 环境准备 | `bun run gda-dev-tools harness setup --project <工程目录>`（按序完成构建、部署、启动引擎、列出工程、核对状态与连通性）；默认完整编辑器，无显示才 headless |
| 只读探针 | `gda status --project <工程目录> --json`、`gda call --project <工程目录> get_engine_version`、`gda call --project <工程目录> system_status` |
| 基线字段 | 开始时间、工具版本、引擎版本、`git rev-parse --short HEAD`、主题与 `draw_id` |
| 登记索引 | `bun run gda-dev-tools jam index`；写入 `examples/INDEX.md` |

工程目录由脚手架生成，命名格式 `<slug>-<hash8>`；不手工拼装。抽题目录只用于读题，不在其中开发、部署或打开引擎。

## 六维夺冠判据

| 维度 | 判据 | 证据 |
| --- | --- | --- |
| Overall | 冷启动无阻断错误、完整流程可走通、完成度达到可上架水准 | 冷启动截图、运行状态、完整流程截图 |
| Gameplay | 核心循环有趣、机制多样、反馈清楚、难度曲线合理 | 试玩截图、输入注入结果、机制清单 |
| Graphics | 画面可辨、美术项目自主创作、风格统一、无占位 | 游戏截图、资源文件与引用读回 |
| Audio | 有自主创作的音乐循环与关键音效并经资源链路接入 | 音频资源文件、播放状态或日志 |
| Innovation | 钩子或机制相对常见玩法有新意，不是换皮 | 机制说明、实现证据、与常见玩法的差异 |
| Theme Interpretation | 主题落到机制、叙事或表现，而非仅贴标题 | 机制与主题对应说明、实现证据 |

任一维仅「可运行」或「缺失」不得声称完成。本表结论与证据引用同时写入结构化自检证据，随每关/每轮保存。

## 素材创作细则

- 美术：先定风格（配色、形状语言、像素/矢量/手绘质感、UI 风格）并贯穿全部画面；用生成工具产出角色、场景、道具、背景、图标、UI 与特效贴图；落盘为 `res://` 资源，经导入与引用链路接入；用瓦片集组织场景地形，用原生节点与内置资源实现特效。
- 音频：用代码或工具生成 PCM 采样并落盘为 `*.wav`/`*.ogg`（写文件后导入）；禁止运行时生成后直接赋给节点属性。至少一条与主题匹配的音乐循环与关键动作音效（跳跃、得分、受伤、胜利、失败等）；用播放器与音频总线控制并确认触发。
- 逐项读回：资源文件存在、节点属性指向 `res://` 路径、运行截图/日志确认生效。

## 目标状态文件（GOAL.md）

位置：工程根 `GOAL.md`，运行时产物；开工写初版，不预建其他结构。字段：

| 字段 | 内容 |
| --- | --- |
| `objective` | 一句话总目标（做出什么游戏、达到什么交付状态） |
| `acceptance` | 可判定验收条件，至少含关卡 ≥3、完整通关 ≥5 分钟、关卡间机制差异、六维自检全部达冠军水准且证据齐全、美术与音频均自主创作并接入、冷启动无阻断错误 |
| `limits` | 预算/时间/范围上限，作为自动推进的停止边界 |
| `state` | 仅取 `active`、`paused`、`budgetLimited`、`usageLimited`、`complete`、`unmet` |
| `completionEvidence` | 完成证据路径或引用（关卡状态、六维结论、素材与引用读回、冷启动/重开/暂停状态、决策日志条目） |
| `blocker` | 当前阻塞点，无则写「无」 |
| `checkpoints` | 按关/按轮的列表，每项含关卡或轮次标识、状态、证据引用、时间戳 |

原子写：任何字段更新先写临时文件再重命名覆盖，不原地多次写入；写入失败保留上一版。

## 结构化自检证据

- 时机：垂直切片完成、每关结束、每轮创意迭代结束、收尾冷启动复验后各产出一份，随检查点保存并登记到 `completionEvidence`。
- 载体：工程根 `SELFCHECK.md`，或每关一个 `SELFCHECK-<关卡标识>.md`；用固定小标题加键值行或表格，便于机器读取。
- 字段：关卡/轮次标识与时间戳；关卡状态（可玩/未完成/阻塞）与本关新增内容摘要；六维结论与证据引用（各给达标/待改进/缺失及截图、读回值、播放证据、机制与主题对应说明，任一维缺失不得判该关达标）；素材创作记录（新增资源文件、生成工具、引用路径与读回结论）；冷启动/重开/暂停三态各一次实际运行结论与证据引用；决策点（关键决策、取舍与下一步）。
- `DEVLOG.md` 默认不建，长程才建，只记决策、阻塞与下一步；未建时决策点直接写在自检证据内。

## 路径约定

| 路径 | 用途 |
| --- | --- |
| `<工程目录>/GAMEJAM.md` | 赛题说明与提交要求，唯一提交要求来源 |
| `<工程目录>/SUBMISSION.md` | 作品说明（默认名） |
| `<工程目录>/GOAL.md` | 长程目标状态（运行时产物，不提交） |
| `<工程目录>/SELFCHECK*.md` | 结构化自检证据 |
| `<工程目录>/DEVLOG.md` | 长程决策日志（可选） |
| `examples/INDEX.md` | 项目登记索引 |
