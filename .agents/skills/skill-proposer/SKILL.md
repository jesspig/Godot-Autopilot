# Skill Proposer

把重复验证的开发习惯蒸馏为可执行提案，只提案不直接写盘。

## 蒸馏门槛

- 同一流程复现至少2次才提案，单次经验只记wiki不提案。
- 用户显式要求时跳过复现计数，直接进入证据读取。
- 只提炼可执行习惯与规则，1:1细节留在wiki不搬运。
- 提案去会话特异，使用类级命名，不带人名日期会话号。
- 无可执行验证任务时不上报，先补验证再提案。

## 证据读取

- 只读docs/wiki/index.md与复现痕迹定位证据，不扫全库。
- 按三层核对来源：Raw 存原始痕迹（`docs/wiki/raw/`）、Wiki 存整理细节（`docs/wiki/`）、Skill 存可执行习惯（`.agents/skills/`）。
- 摘录复现次数、触发场景与差异点，单次痕迹直接退回。
- 引用路径只用相对路径，不写绝对路径。
- 证据不足时停止提案，注明缺失项。

## 提案结构

- 写清触发语：列出真实触发句与不触发情形。
- 写清流程：用编号列表写固定步骤与判断点，不写散文。
- 写清验证：给出试跑任务与期望输出，无验证不准入。
- 写清边界：列出输入输出范围与明确非目标。
- 附件按需声明：缺脚本不配脚本，缺引用不拆引用。

## 门控与写入

- 只产提案文本供人审阅，人审通过前不写盘。
- 通过后写入相对路径 `.agents/skills/<skill-name>/SKILL.md`，不新建多余文件。
- 目标已存在同类习惯时提patch合并，不新建重复项。
- 每次提案先查 `docs/wiki/maintenance-log.md` 防重复，再记 accepted/rejected/deferred 一笔，行格式为「日期 | 提案 | 状态 | 理由」。

## 生命周期

- 合并重复提案，剪枝失效规则，归档过期习惯。
- wiki记录常留，skill变更可回滚，不删wiki补救。
- 每次维护会话开始时复查提案状态，同步更新 `docs/wiki/maintenance-log.md` 结论。
- 防过拟合：复现样本变化即重验证，不固化偶发细节。
