# Wiki 维护者

## 触发条件

- 功能完成、操作指南交付，或统一提交前需要同步知识库时触发。
- 用户查询知识时仅执行查询协议，不顺带更新文档。
- 例行代码修改、未完成工作和无相关事实变化时不触发维护。

## 查询协议

1. 先读知识库索引，按索引描述选出最相关页面。
2. 命中后最多读取 3 个正文页面；答案只能来自已读取内容，并链接引用来源。
3. 找不到依据时明确说明未知，不根据页面标题或记忆补全事实。

## 更新协议

1. 更新前读取常驻指令、知识库索引及受影响正文；以源码和实际测试为事实标准。
2. 用 git diff HEAD 确认真实变更范围，忽略仅由 CRLF 造成的状态噪声；只更新受影响页面。
3. 一项知识只保留一个权威落点：稳定且每次会话必需的规则归常驻指令，陈述性事实归知识库，可执行步骤归项目技能册。
4. 数值从当前运行时统计或可复核测试重新计算；不得从旧文档复制成当前事实。无法核实的内容标记为待补充。
5. 每个正文页维持现有 frontmatter 规则：type、title、description、tags、timestamp、resource；时间使用真实 ISO 8601。至少有一条指向仓库真实文件的相对链接。
6. 同步维护知识库索引的链接与一句话描述、知识库日志的最近 7 天汇总，以及当日 changelog 记录；核对链接有效、描述未过时。
7. 检查受影响的项目技能册：若知识库事实变化使步骤、判据或验收失效，提出并同步修正；避免在知识库复制操作流程。

## 验收

- 每个新增或修改断言均可追溯到源码、测试或用户明确确认。
- 索引、正文、日志与当日记录一致；本轮变更不引入断链或过时描述。
- 按改动风险运行相关测试；未运行时明确报告，不把静态检查描述为测试通过。
- 汇报变更路径、事实依据、验证证据和遗留不确定项。

## 禁止事项

- 不全量重写知识库，不编辑无关页面，不删除源文档。
- 易漂移计数不写入常驻指令；数值以运行时统计为准。
- 不静默放宽安全默认值；涉及监听、授权、脱敏、导出期拒绝或主线程契约时，按安全与并发契约核验。
- 不因本技能被触发而自动执行范围外动作；遇到目标超出本范围时说明边界。
