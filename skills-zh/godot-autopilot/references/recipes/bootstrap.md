# bootstrap

## 1. 触发条件与输入
当新代理、新 shell 或新项目会话需要在任何改动前先确认连接可用时，使用本配方。输入：项目目录（可选）、已知实例 id 或 socket（可选），以及用于发现的搜索词与工具名（可选）。

## 2. 前置检查
CLI 在 PATH 上，本地控制平面可达。若要指定实例，需知道保存其数据的项目目录。此时不假设任何写操作。

## 3. 可复制的 CLI 命令
```bash
gda ping
gda status --format json
gda doctor run --offline
gda tool list
gda tool search scene
gda tool describe get_scene_tree
gda project list
gda editor list --all-projects
gda skill list
gda docs status
```
复杂参数请从文件或 stdin 传入，不要猜测工具名：
```json
{
  "action": "list",
  "category": "scene"
}
```

## 4. 每步观察字段
每次调用都读取信封字段 ok、error、data、meta、warnings。健康探测确认可达性；状态调用确认绑定的项目与实例字段；诊断收集失败的检查与修复代码。工具列表、搜索与描述给出后续依赖的规范工具名、必填参数、声明的副作用与风险标注。技能列表与文档状态显示离线可用的本地技能书和文档缓存。

## 5. 验证与退出条件
健康探测成功、状态调用报告目标项目、且每个计划调用的工具至少被描述过一次，即可退出。退出码：零为成功，一为业务失败，二为环境失败，三为用法错误，四为需要确认，五为拒绝确认，一百三十为被中断。

## 6. 失败分支
健康探测失败时运行诊断并查看 CLI 日志尾部；没有列出实例时检查实例列表与项目列表；工具名未找到时用更宽的查询重新发现并再次读取其 schema，绝不编造名字。

## 7. 安全与确认点
发现类调用是只读的。若调用返回 confirmation_required，先读取工具、目标、风险与参数摘要，再用 --confirm 重试同一调用。非交互会话缺少确认即停止。结果未知时不要重发调用，先查任务列表。把破坏性、进程、代码执行或游戏运行时信号视为停下审查点。

## 8. 明确不做什么
不硬编码工具数量、别名表、版本窗口或迁移历史。不在未描述的情况下猜测工具名或参数。本配方不执行写入、安装或游戏运行时变更。
