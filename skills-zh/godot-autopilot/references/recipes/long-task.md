# long-task

## 1. 触发条件与输入
当命令标记为长时间运行、你希望流式查看进度而不是阻塞等待，或运行需要跨连接中断存活时，使用本配方。输入：要启动的测试套件或场景、分离式调用返回的任务 id，以及用于轮询的超时、重试与游标值。

## 2. 前置检查
你已记录打算分离执行的命令及其预期结果字段。你知道要观察的实例与代际绑定，或者会从任务列表中发现它。你有写入进度或报告的位置。

## 3. 可复制的 CLI 命令
```bash
gda test run --label smoke --detach
gda job list
gda job status <id>
gda job wait <id> --timeout 600 --progress
gda job logs <id> --cursor 0 --limit 50
gda job cancel <id> --confirm --reason superseded
gda debug repro --path res://scenes/main.tscn --confirm --detach
gda script test --directory tests --timeout 120
gda test status <id>
```

## 4. 每步观察字段
分离式调用立即返回任务 id，并把进度写到标准错误。从任务列表读取 id、状态以及实例或代际绑定。状态显示当前阶段与终态。等待会在重连后保留终态结果；读取其保留状态与进度行。按游标取日志得到有序事件。取消报告实际到达的阶段，而不只是请求本身。场景复现与测试运行各自报告运行状态与结果数量。

## 5. 验证与退出条件
任务进入终态、结果与预期字段一致、进度和日志已采集、无需继续轮询，即可退出。被取消的任务只有在取消阶段被确认后才算退出。

## 6. 失败分支
等待时连接中断则重新检查状态并带重试再次等待，不要重新提交工作。任务 id 未知时列出任务并按标签与代际匹配。日志为空时从头游标开始。必须停止运行时用 --confirm 取消并核实报告的阶段；读回之前不要假定取消已成功。

## 7. 安全与确认点
取消任务和运行场景复现属于高风险动作。调用返回 confirmation_required 时，审阅工具、目标、风险与参数后，用 --confirm 重试同一调用。非交互会话缺少确认即停止。结果未知的调用不要重发，应改用任务记录。把破坏性、进程、代码执行或游戏运行时信号视为停下审查点。

## 8. 明确不做什么
不硬编码工具数量或版本窗口。不假设任务 id 格式或代际编号。读取终态之前，不把分离式调用视为已完成。
