# 测试计划（GDA E2E 测试床）

本文规定本工程作为 godot-autopilot（GDA）MCP 插件端到端测试床时的测试目的、目标、约定、证据要求与记录规范。

## 测试目的

通过"在已建成的 3D 工程上执行可复验的编辑器操作"，评估 GDA 能否支撑 AI 客户端**打开场景、检查节点与配置、运行游戏、验证 3D 视角与物理行为、截图取证**，并客观记录工具与文档的表现。

## 测试目标（评估维度）

1. **工具可用性**：场景打开、节点检查、属性读回、运行控制、截图是否可用；失败时错误是否可操作。
2. **3D 检查能力**：场景树、变换、相机视角、碰撞体、生成路径是否可查可验。
3. **物理与配置可读性**：输入动作、物理层、Jolt/插值/tick、自动加载、信号连接是否可读回（注意工作树模板缺失项，见 [tdd.md](../tech/tdd.md)）。
4. **文档自主性**：本目录文档是否只记录现状、可独立执行、无矛盾引用、无编造路径。
5. **真实交付**：运行后可移动、可跳跃、可压扁得分、可失败重试；不接受"看起来完成"。
6. **流程完整性**：打开 → 运行 → 压扁 → 被撞 → 重试构成闭环；重试后回到初始态。
7. **记录规范**：问题记录含五要素（见下）；优秀表现同样如实记录；不夸大、不贬低。

## 测试约定

- 游戏工程文件（`*.tscn`、`*.gd`、`project.godot` 等）**只读**，用于核对；不修改 `docs/` 之外的任何文件。
- **不运行 Godot 构建**（本任务不执行构建命令）；运行验证指在编辑器/已配置环境中按验收步骤执行，具体方式以测试执行者环境为准并如实记录。
- 所有结论基于实际发生的事件；证据随测试报告留存。
- 测试期间不更新本仓库的 wiki。
- 配置差异前置确认：执行前先记录以哪份 `project.godot`（工作树模板 vs 源库原件）启动，凡受影响项（音乐自启、输入、物理）如实记录。

## 证据要求（含截图）

**逻辑断言不是完整证据；涉及画面效果的验收必须看图。**

| 验收类型 | 必须提供的证据 |
|---|---|
| 逻辑行为（计分、重试、生成、销毁、信号） | 运行日志或可读回的状态值（截图可选） |
| **对象摆放与结构**（场景树、地面/墙/路径/相机/碰撞体） | **编辑器界面截图**：视口 + 场景树/检查器 |
| **运行画面效果**（3D 视角、角色/小怪同框、HUD、重试遮罩） | **游戏运行界面截图**：真实运行中抓取 |
| **物理行为**（移动、跳跃、压扁弹跳、被撞、生成冲锋） | **游戏运行界面截图或连续截图**：行为前后同框 |
| **音乐自动播放** | 编辑器 autoload 配置截图 + 运行状态（有/无声音如实记录） |

## 问题记录格式

每个问题必须包含：

1. **触发场景**：在做什么时发生；
2. **详细操作步骤**：可复现的步骤序列（含打开的场景、按的键）；
3. **预期行为**：文档或工具声称的行为；
4. **实际表现**：真实观察到的结果（附证据）；
5. **问题分析**：基于事实链的推断，无法定位根因时如实说明边界。

## 终止条件

- 若因 GDA 功能缺失或致命缺陷导致验证无法继续，可基于事实终止并转入报告编写。
- 引擎崩溃不尝试重启（本任务亦不运行引擎）；记录现象并结束本轮测试。

## 输出

- 测试报告：`report/<YYYY-MM-DD-HH-mm>-report.md`（仓库根目录的 `report/`，非本文档目录）。
- 报告应包含：工具与文档的总结性评估、按优先级排序的优化建议、全部问题记录与证据索引、配置差异说明、工作树模板缺失项的影响。
