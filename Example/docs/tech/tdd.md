# 技术设计文档（TDD）

本文只规定**边界**：引擎的硬约束、工程的只读输入、运行时目标，以及"实现自由"的明确声明。它**不是**架构说明书——本文不提供目录结构、节点树、脚本划分、命名规范或任何操作步骤。

## 硬约束

1. **引擎**：Godot 4.x 工程；2D 游戏；**三关流程 + 菜单系统**（主菜单 → 选关 → 游玩 → 结算 → 解锁）。
2. **素材只读**：`assets/` 下的原始文件不修改、不重命名；工程内引用时保持路径原样（见 [../art/asset-catalog.md](../art/asset-catalog.md)）。
3. **玩法数值**：以 [../gdd/mechanics.md](../gdd/mechanics.md) 为准（含移动/跳跃、敌人、箱子、命数、菜单状态）；数值可因实现可行性微调，但必须记录差异与验证证据。
4. **关卡实例**：以 [../gdd/level-design.md](../gdd/level-design.md) 为准（`level_01/02/03` 的区域、坐标、敌人巡逻区间与轨道端点）；坐标与区域语义可微调，但必须记录差异与验证证据。
5. **唯一写盘例外**：除 `user://save.cfg` 的 `[progress] unlocked`（int，默认 1，上限 3）外，不得写入任何磁盘文件；检查点与收集状态仍只保留在会话内。删档即重锁是可测试行为。
6. **交付可复验**：最终必须能从工程入口启动进入主菜单，并完整走通"选关 / 通关解锁 / 死亡重生 / GameOver / 暂停退出"路线，运行期间无脚本错误与缺失资源告警。
7. **本目录是设计的唯一来源**：不要从其他文档、旧版本或文件名反推需求。

## 明确不规定（实现自由）

以下内容**全部由实现者自行决策**，任何示例都不应被当作模板：

- 目录结构、文件命名、场景/节点/脚本的划分方式（含菜单场景与关卡场景如何组织）；
- 使用哪些引擎特性、API、节点类型与资源格式；
- 存档的具体读写方式（`ConfigFile` 或其他，满足第 5 条的路径与键语义即可）；
- 暂停的具体实现方式（`SceneTree.paused` 或其他，满足"physics 与计时冻结"即可）；
- 碰撞层/掩码的位分配（只需满足语义：地形阻挡玩家、敌人/危险/收集/进度各自只监听玩家、互不串扰）；
- 信号/事件/接口的命名与连接方式（只需满足 [../gdd/mechanics.md](../gdd/mechanics.md) 的行为契约与幂等要求）；
- 实现顺序、验证方式与采用的工具链（包括但不限于编辑器 MCP 工具、脚本、手动操作）；
- 窗口/分辨率策略（只需满足像素艺术的整数缩放要求，见 [../art/art-direction.md](../art/art-direction.md)）；
- 调参过程与中间态。

> 测试执行按 [../test/test-plan.md](../test/test-plan.md) 的“增量循环执行法”节奏交付证据；目录结构、节点/脚本划分与实现手段的自由不变，两者不冲突。

## 语义约束（设计要求，实现方式自定）

- **碰撞语义分离**：玩家、地形、敌人、危险、收集品、进度对象必须互不误触发（例如敌人不得触发收集品计数或检查点激活；危险不应对收集品或进度对象生效）。
- **敌人语义**：敌人只监听玩家；踩头（玩家下落中且脚底高于敌人顶部容差）杀死敌人并给玩家弹跳，其余接触杀死玩家；敌人死亡是一次性状态。
- **命数语义**：整局 `lives=3` 开局；死亡扣 1；归零进入 GameOver；通关 +1（上限 5）；R 重打本关 `lives` 不变。
- **状态闸门**：死亡与胜利必须是一次性状态；进入后忽略后续的收集、危险与输入（见 [../gdd/mechanics.md](../gdd/mechanics.md) 的不变式）。
- **暂停语义**：暂停期间 physics 与关卡计时冻结；Resume 必须回到完全相同的玩法状态。
- **解锁语义**：通关即把 `unlocked` 推进到下一关（上限 3）；选关界面未解锁关卡置灰锁定、不可进入。
- **会话状态**：检查点与收集集合仅存在于当前运行会话；重开关卡即清空；`lives` 贯穿整局（GameOver 或回到主菜单重开新局时重置为 3）。
- **可观测性**：关键事件（死亡、收集、检查点、胜利、敌人死亡、解锁写入、暂停进出）应能在运行日志或 HUD 中被观察到，便于验收。

## 运行时目标

| 项目 | 目标 |
|---|---|
| 帧率 | 桌面环境稳定 60 FPS（三关规模下无卡顿） |
| 启动 | 从工程入口启动即进入主菜单，无阻塞性报错 |
| 存档 | 通关正常写入 `user://save.cfg`；缺失或损坏时按默认（`unlocked=1`）启动，不崩溃 |
| 日志 | 无脚本错误、无缺失资源告警、无跨线程/引擎级错误 |
| 输入 | 键盘可完整游玩（含暂停、确认、重开） |
| 暂停 | 暂停菜单五项可用；暂停期间游戏世界冻结 |
| 退出 | 主菜单与暂停菜单可退出游戏；关闭窗口即退出，不残留进程 |
