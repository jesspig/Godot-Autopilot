# 技术设计文档（TDD）

本文只规定**边界**：引擎的硬约束、工程的只读输入、运行时目标，以及"实现自由"的明确声明。它**不是**架构说明书——本文不提供目录结构、节点树、脚本划分、命名规范或任何操作步骤。

## 硬约束

1. **引擎**：Godot 4.x 工程；2D 游戏；单关卡运行流程。
2. **素材只读**：`assets/` 下的原始文件不修改、不重命名；工程内引用时保持路径原样（见 [../art/asset-catalog.md](../art/asset-catalog.md)）。
3. **玩法数值**：以 [../gdd/mechanics.md](../gdd/mechanics.md) 为准；数值可因实现可行性微调，但必须记录差异与验证证据。
4. **关卡实例**：以 [../gdd/level-design.md](../gdd/level-design.md) 为准；坐标与区域语义可微调，但必须记录差异与验证证据。
5. **交付可复验**：最终必须能从工程入口启动并完整通关（含死亡重生与幂等路线），运行期间无脚本错误与缺失资源告警。
6. **本目录是设计的唯一来源**：不要从其他文档、旧版本或文件名反推需求。

## 明确不规定（实现自由）

以下内容**全部由实现者自行决策**，任何示例都不应被当作模板：

- 目录结构、文件命名、场景/节点/脚本的划分方式；
- 使用哪些引擎特性、API、节点类型与资源格式；
- 碰撞层/掩码的位分配（只需满足语义：地形阻挡玩家、危险/收集/进度各自只监听玩家、互不串扰）；
- 信号/事件/接口的命名与连接方式（只需满足 [../gdd/mechanics.md](../gdd/mechanics.md) 的行为契约与幂等要求）；
- 实现顺序、验证方式与采用的工具链（包括但不限于编辑器 MCP 工具、脚本、手动操作）；
- 窗口/分辨率策略（只需满足像素艺术的整数缩放要求，见 [../art/art-direction.md](../art/art-direction.md)）；
- 调参过程与中间态。

## 语义约束（设计要求，实现方式自定）

- **碰撞语义分离**：玩家、地形、危险、收集品、进度对象必须互不误触发（例如危险不应对收集品或进度对象生效）。
- **状态闸门**：死亡与胜利必须是一次性状态；进入后忽略后续的收集、危险与输入（见 [../gdd/mechanics.md](../gdd/mechanics.md) 的不变式）。
- **会话状态**：检查点与收集集合仅存在于当前运行会话；重开关卡即清空。
- **可观测性**：关键事件（死亡、收集、检查点、胜利）应能在运行日志或 HUD 中被观察到，便于验收。

## 运行时目标

| 项目 | 目标 |
|---|---|
| 帧率 | 桌面环境稳定 60 FPS（本关卡规模下无卡顿） |
| 启动 | 从工程入口启动即进入关卡，无阻塞性报错 |
| 日志 | 无脚本错误、无缺失资源告警、无跨线程/引擎级错误 |
| 输入 | 键盘可完整游玩（含重开） |
| 退出 | 关闭窗口即退出，不残留进程 |

## 验收方式

- 顶层验收与分项验收清单见 [../README.md](../README.md) 与各设计文档末尾，汇总在 [../test/acceptance.md](../test/acceptance.md)。
- 允许在不违反"素材只读"与"必做范围"的前提下采用任何实现方式；验收只检查行为与表现，不检查实现结构。
- 涉及画面效果的验收项必须提供截图证据（编辑器或游戏运行画面），详见 [../test/test-plan.md](../test/test-plan.md)。
