# 测试计划

本文规定本工程作为 **godot-autopilot（GDA）MCP 插件测试床**时的测试目的、目标、约定、证据要求与记录规范。

## 测试目的

通过"从零开发一款完整可玩的单关卡游戏"这一真实任务，评估 GDA 能否让 AI 客户端**仅凭设计文档与素材**完成开发，并客观记录工具与文档在实际使用中的表现。

## 测试目标（评估维度）

1. **工具可用性**：各工具能否完成其宣称的功能；失败时错误信息是否可操作；工具描述与 Skill 文档是否与实际行为一致。
2. **工具完备性**：完成游戏开发所必需的能力是否存在；缺失时是否存在可接受的替代路径。
3. **参数与数据合理性**：工具参数设计是否自洽；返回值是否足够支撑下一步决策；写入是否有校验、读回是否可信。
4. **文档自主性**：设计文档是否只描述"做什么"；是否给实现者留出设计空间；是否存在误导实现的内容（错误伪代码、矛盾几何、含糊验收）。
5. **真实交付**：最终交付是否可运行、可通关、可复验。不接受"看起来完成"。
6. **流程完整性**：主菜单 → 选关 → 游玩 → 暂停 → 结算 → 解锁 → GameOver 是否构成闭环；暂停是否真正冻结世界；退出路径是否干净。
7. **敌人与命数**：三型敌人行为是否符合规格；踩头与侧碰判定是否正确；命数增减与 GameOver/通关奖励是否正确；解锁写入是否准确。
8. **记录规范**：问题记录包含五要素（见下）；表现优秀处同样如实记录；不夸大、不贬低。

## 测试约定

- 游戏工程文件（`*.tscn`、`*.tres`、`*.gd`、`project.godot` 等）的创建与修改**仅通过 GDA 完成**；允许以只读方式查阅工程文件用于核对。
- **不主动重启 Godot 引擎**；若引擎意外崩溃，如实记录现象并结束本轮测试。
- 所有结论必须基于实际发生的事件；证据随测试报告留存。
- 测试期间不更新本仓库的 wiki 内容。
- 存档相关测试允许删除 `user://save.cfg`（删档重锁验证）；删档前记录当时的 `unlocked` 值，测后如实记录是否恢复。

## 增量循环执行法

开发必须按人类式增量循环推进：**搭场景 → 写代码 → 运行看效果 → 加新功能**，往复循环；禁止一次性生成全部代码与场景、最后再一次性测试。

### 四拍

| 拍 | 名称 | 要求 |
|---|---|---|
| 1 | 搭 | 只建本环需要的最小场景与节点（先环境后角色，先占位后美术） |
| 2 | 写 | 只写本环的代码并挂载，不提前写未来功能的代码 |
| 3 | 看 | 运行并截图：编辑器视口核对摆放，游戏运行核对行为；截图即证据 |
| 4 | 定 | 本环验收项全过才进入下一环；手感数值问题当场微调，不带病进入下一环 |

### 铁律

1. **单循环只做一个功能增量**：多个功能的步骤不得合并到同一环。
2. **失败只回滚本环**：定位到环后在本环内修复，不扩大范围。
3. **每环留一句话记录**：写清本环改了什么、截图看到了什么。

### 循环切分（level_01 垂直切片先行）

| 环 | 搭 | 写 | 看（验收） |
|---|---|---|---|
| 1 | 工程入口 + `level_01` 地形（仅地面/平台/墙体）+ 背景 | 无逻辑 | 编辑器截图：地形连续、尺寸正确 |
| 2 | 玩家角色场景（占位方块即可）+ 出生点 | 左右移动 + 基础跳 | 运行截图：能跑能跳、相机跟随 |
| 3 | — | 二段跳 + 墙滑/墙跳 | 运行截图：跳高与双墙通过 |
| 4 | 尖刺 + 检查点 + 终点 + 水果各 1 | 死亡重生 + 收集计数 + 胜利锁定 | 三条路线走通（通关/死亡/幂等） |
| 5 | 正式美术（角色动画、地形贴图）+ HUD | 动画状态映射 + HUD 绑定 | 视觉验收截图 |
| 6 起 | 每环只加一个新物：巡逻怪 → 踩头 → 箱子 → 锯/火 → 菜单 → 暂停 → 存档 | 同环逻辑 | 同环行为截图 |

第 2 环允许用占位方块代替正式角色美术：美术不到位不阻塞手感验证（先跑通再美化）。

### 证据归档

每环截图随测试报告存入 `report/img/`，并在报告中标注每张截图对应的环编号与验收项。

## 证据要求（含截图）

**逻辑断言不是完整证据；涉及画面效果的验收必须看图。**

| 验收类型 | 必须提供的证据 |
|---|---|
| 逻辑行为（计数、幂等、状态闸门、参数） | 运行日志或可读回的状态值（截图可选） |
| **对象摆放与锚点**（贴地、悬空关系、位置关系） | **编辑器界面截图**：视口 + 场景树/检查器（展示结构与位置） |
| **运行画面效果**（相机跟随、动画切换、HUD、胜利/死亡表现） | **游戏运行界面截图**：在真实运行中抓取 |
| 地形/平台/墙体通过性 | 运行截图或逐段截图（包含角色与地形同框） |
| **菜单与结算**（主菜单、选关锁定态、暂停菜单、通关结算、GameOver） | **游戏运行界面截图**：每种界面至少一张，选关须拍到锁定与解锁对比 |
| **敌人与箱子**（巡逻/轨道/喷发、踩杀、顶箱子） | **游戏运行界面截图**：敌人在其活动区间内与玩家同框 |

截图证据建议随测试报告归档（如 `report/img/`），并在报告中标注每张截图对应的验收项。

## 问题记录格式

每个问题必须包含：

1. **触发场景**：在做什么时发生；
2. **详细操作步骤**：可复现的步骤序列；
3. **预期行为**：文档或工具声称的行为；
4. **实际表现**：真实观察到的结果（附证据）；
5. **问题分析**：基于事实链的推断，无法定位根因时如实说明边界。

## 终止条件

- 若因 GDA 的功能缺失或致命缺陷导致游戏无法继续开发，可基于事实终止开发并转入报告编写。
- 引擎崩溃不尝试重启；记录现象并结束本轮测试。

## 输出

- 测试报告：`report/<YYYY-MM-DD-HH-mm>-report.md`（仓库根目录的 `report/`，非本文档目录）。
- 报告应包含：工具与文档的总结性评估、按优先级排序的优化建议、以及全部问题记录与证据索引。
